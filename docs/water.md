## NAME

**water** -- `.wat` ⇄ `.wasm` converter: assembler and folding disassembler

## SYNOPSIS

```
water file.wat -o file.wasm         # assemble (verifies by default)
water --no-verify bad.wat -o f      # assemble without §7 — the fixture path
water -d file.wasm                  # disassemble: folded .wat on stdout
water -d file.wasm --width 80 -o f  # narrower line budget (default 100)
```

One tool, two directions, two opposite contracts — and the contracts are the
point.

## OPTIONS

**-d**
: Disassemble: `.wasm` in, folded `.wat` out. Validates first; a rejected
  module produces a diagnostic (function, instruction ordinal, mnemonic,
  §7.6 reason, and the operand stack at that point) and NO output file.

**-o**, **--output** *F*
: Output file. Omitted or `-`: stdout (binary output to a terminal is
  refused).

**--width** *N*
: The `-d` line budget (default 100). Layout only — §6.1.1 makes white space
  free, so this decides nothing about validity.

**--no-verify**
: Assemble without §7 verification, restoring the pure transcription. This is
  how the conformance pipeline produces deliberately-invalid modules for the
  engine to reject; the emitted bytes are identical to the always-unverified
  library path's, and a pinned test holds them so.

## DESCRIPTION

water converts between WebAssembly's two module encodings, §5 binary and §6
text, against WebAssembly Core 3.0. The two directions deliberately do NOT
mirror each other:

**text → binary is transcribe-only.** `wat_assemble` builds exactly the module
the text describes and never validates it. That is how a structurally-fine but
§7-invalid fixture reaches the engine to be rejected for the right reason —
the conformance suite's reject-direction gates depend on it. What the text
says, the binary gets.

**binary → text validates first and only ever writes valid text.** A folded
rendering is a claim about the data flow, and on a body whose operand stack is
wrong that claim would be a lie. There is no flat mode and no partial file: a
module that fails §7 produces a diagnostic and nothing else.

### Folding

§6.1 defines text as *"a rendering of their abstract syntax into
S-expressions"*, well-formed **iff** generated by the grammar, and §6.5.11
makes folded instructions pure rewrite sugar. water renders the folded form,
and which grouping is *the operands* comes from §7.6 itself: the validation
walk records, per operand, the instruction that pushed it (the spec's own
no-dup invariant makes those edges a tree), and the admissible fold depth is
the largest suffix of operands whose producing run is exactly their subtrees.
A `nop` between operands bounds the fold; dead code below the frame height
bounds it; `block`/`loop`/`try_table` admit none (§6.5.11 gives only `if` a
`foldedinstr*` slot). Linear input comes back folded:

```wat
(func (type 0) (param i32) (result i32)
  (i32.mul (i32.add (local.get $x) (i32.const 2)) (i32.const 3)))
```

— which is the §6.5.11 Note's own example, and the pinned target string.

### Layout

The render tree's schema, layout grammar, per-rule segment rows and node type
are four projections of ONE generator walk (`tools/gen_wat_ir.c` over
`spec/wat_module.asdl` + `spec/instructions.toml`), so they cannot disagree;
burgc's `--coverage --strict --asdl-strict` proves every §6 production has a
rendering rule, and every grammar cost is the byte length of that rule's own
literals. A group lays flat exactly when the line fits its computed width
(plus the pending closers); breaking only moves white space, which §6.1.1
makes free. The engine self-checks: every flat group's emitted bytes must
equal its predicted width, over the whole corpus, in the exit code.

### Nothing is lost

Custom sections ride §7.7.3 `(@custom "name" (before|after sec) data…)`
annotations with explicit placement — written by the renderer, CAPTURED by
the reader (the one annotation that is not white space to water), and
re-inserted at their placement slots during assembly, so a module with custom
sections round-trips byte-identically. `tag` is absent from the spec's place
vocabulary; a custom section beside the tag section anchors on its other
neighbour, and a position no word can express is counted on its own gated
line, never silently misplaced.

The §7.7.1 name section is additionally READ (`spec/wasm_names.bbq`, a
generated reader) to spell §6.6.1 identifiers at every binding and use site:
module, functions, types, tags, struct fields, params and locals. Names need
not be unique or identifier-clean, so a name becomes an id only when it is
nonempty, all-idchar, and the first of its spelling in its space; a local is
named only when its run-length group is a singleton, because an id on a
`(local …)` clause means exactly one local and splitting a run would move
bytes. Identifiers are erased by re-parsing — readability is free, and the
round trip stays byte-exact. `@name` annotations are never emitted (§7.7.3:
the name section already rides its own `@custom`, and both would make two).

Floats print as hex floats (§6.3.2: *"Rounding can be prevented by using
hexadecimal notation"*), `inf` / `nan` / `nan:0x…` for the specials — NaN
payloads, signed zeros and subnormals re-read bit-identically.

## GATES

Every claim above is a counter in `test_wast`, printed and OR'd into the exit
code (a printed number is a gated number):

| counter | holds |
|---|---|
| `wast §7 differential (water vs engine)` | water transcribes §7.6+§3.5 itself, sharing only generated tables with the engine; both must agree on every module, accept AND reject |
| `wast §7.6 edge differential (water vs tier-2 tree)` | the producer edges agree with the JIT's independently-written tree walk, edge for edge |
| `wast wat width honesty` | every flat group's bytes == its predicted width; every line fits or its overflow is one unbreakable token, counted |
| `wast wat re-read` | every rendering of every accepted module parses back through the real `.wat` reader |
| `wast custom placement` | no custom section at a position §7.7.3 cannot express |

```
wasm/spec/wat_module.asdl    the render tree's module half (hand authority)

wasm/spec/instructions.toml  the 497-instruction vocabulary (spec-derived)

                             wat_render.h and the production inventory

                             token spelled once

```
